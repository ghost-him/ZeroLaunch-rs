# ZeroLaunch Wiki 写作规范（用户 Wiki 正文生成/修订）

目标目录 由用户指定，在调用该skill前，需要直接向用户提问本地目标目录为哪里（由用户负责将远端 `ghost-him/ZeroLaunch-rs.wiki` 同步到本地目录上）。

`src-tauri/assets/wiki/` 是 GitHub wiki 的**自动拉取镜像**（构建期嵌入为程序内「使用手册」），禁止在那里编辑：改动无法同步回 wiki，下次拉取会被覆盖。手册正文只改本 skill 指向的 wiki 仓库。

## 结构铁律（2026-10 重构后）

GitHub wiki 是**扁平命名空间**：页面标题 = 文件名，目录不参与路由，`名/README.md` 只会塌缩成同名页面（实测 `/wiki/插件生态/README` 直接重定向首页）。因此：

- **所有页面平铺在仓库根目录**，禁止子目录、禁止 `README.md`/`index.md` 这类索引页。
- 导航只有两处：`Home.md`（唯一文档地图，六组表格）与 `_Sidebar.md`（右侧栏分组导航，GitHub 自动渲染）。文件名不要含 `\ / : * ? " < > |`。
- 页面内链统一 `[显示名](页面名)`：不写 `.md`、不写目录；页面名必须与目标文件名完全一致。
- 当前共 58 个内容页 + `Home.md` + `_Sidebar.md`。六组（仅作 Home/Sidebar 分组，不落目录）：入门与基础、核心搜索体验、扩展搜索源、深度定制与配置、插件生态、高级维护与工具。
- 被移除的页面（如 `远程配置同步`）不要再引用；GitHub 会把失效页面 URL 重定向到首页。

## 页面铁律

1. **正文用户导向**：只写「在哪个设置分组勾什么 / 按哪个快捷键 / 输入什么 / 看到什么」。模块名、函数名、RPC、schema、结构体只允许出现在文末单行 `> 代码依据：文件:行号（说明）` 脚注。
2. 概念用日常语言（"语义搜索=让 AI 读懂意思"），不用 embedding/向量当叙述主体。
3. 代码块只放用户要输入的东西（命令、网址模板、快捷键表、配置值），禁止源码/JSON schema。
4. 结构：`# 标题` → 简介 → `## 使用` → `## 配置`/`## 注意事项`/`## 已知限制` → 文末代码依据行。正文 200–500 中文字；全文只出现一次「代码依据」。
5. 代码即真理：`src-tauri/src/`、`src-ui/`、`crates/` 现状优先；旧 README、`REQUIREMENTS_DOCUMENT.md`、archive 只当线索。

## 配置保存语义（易写错，2026-10 已核实）

所有内置配置组件的 `commitPolicy` 都是 `Staged`：改动后必须点页面底部 **应用** 才生效，**没有任何组件自动保存**。不要在页面里写"即时生效/自动保存/无需点应用"；正确写法是"保存后即时生效（无需重启）"。恢复默认走 **重置为默认**。

## 高频事实/陷阱（写前 grep 核实）

- 结果屏蔽已实现：结果右键「不再显示」三选一面板 + 设置→搜索管道→结果排除规则表（exact/path_prefix/contains），对全部数据源与插件候选生效；插件候选/行内插件结果无此项。
- 路径/网址检测必须**提交**才接管：路径后打一个空格（尾随空白）或用成对英文双引号；无空格裸路径不接管。全屏/普通设置同理不要漏掉"空格提交"。
- WebDAV、自定义保存路径、存储后端已整体移除；配置固定本地 `$HOME/.ZeroLaunch-rs/config/zerolaunch_config.json`，不要创建"远程配置同步"页。
- 回车优先唤醒：窗口行为 `wake_existing_first`，默认关；仅对注册了唤醒动作的目标生效。
- 托盘：常规设置「显示系统托盘图标」默认开；菜单项固定为 设置窗口/刷新数据库/重新注册快捷键/游戏模式/退出程序。
- `> ` 行内命令（cmd-run）在可见 cmd 窗口执行，不解析 `{}` / `{clip}`；预置自定义命令走后台无窗口。
- 本机 CLI 服务（`zl` 命令行工具）默认开，可在 常规设置 →「本机 CLI 服务」关掉：立即停止监听（token 文件保留），重新打开立即恢复，都不用重启。
- 插件协议 2.0（仅比 major）；`manifest.toml` 只有 `[plugin]` 段必填，`[runtime]`/`[components]` 缺省为空；元数据只从清单构造，无上报通道。
- 插件市场列表/卡片有 24h 本地缓存 + 手动刷新；限流时回落缓存。
- 设置侧边栏顺序：常规设置、外观设置、模型管理、搜索管道、插件、插件市场、调试工具（仅调试模式）、关于、问 AI。

## 多 agent 派发经验

- 按 Home 的六组切页派发，每组一个 agent，互不重叠；任务里给足已核实事实（提交号/文件路径），禁止 agent 深挖超时。
- 超时恢复：让 agent「停止一切新研究」，主 agent 打包结论，限时落盘。
- 收尾校验（机械）：① 文件名唯一、无目录、无 README；② 所有 `](页面名)` 目标存在、无 `.md`/裸斜杠；③ 每页恰好一个 H1 与一条「代码依据」；④ Home 与 `_Sidebar` 覆盖全部内容页；⑤ `git push` 后用 `curl` 检查线上 Pages 列表无重名、关键页 200、抽检新文案存在。
